## 1. 产品重新定义

**一句话**: Sky = 一个只有对话的壳。没有传统应用的页面/面板/导航——所有功能都是 AI 在对话里
**现场理解 → 调用 cap → 实时渲染出 UI** (内联卡片 / 悬浮窗 / 全屏页), 用完即走。

三条铁律:
1. **对话是唯一的常驻 UI**。内置 HTML 只保留: 消息流 + 输入区 + 最小会话触点。
2. **一切其他 UI 由 AI 渲染**。文件浏览、设置、工作区、能力面板、仪表盘——全部是 AI 用
   `cap.ui.*` 现场生成的产物 (artifact), 有生命周期 (打开/关闭/聚焦), 不内置于壳。
3. **cap 层是稳定地基**。现有 31 个 cap 全部保留, 为渲染协议新增 cap.ui.window / cap.ui.artifact 等。

## 2. 三种方案

### 方案 A — 「对话即应用」单栏极简

```
┌──────────────────────────────┐
│ ☰  Sky          ✦ 31 caps  ⚙ │  ← TopBar 极简 (菜单/徽章/设置入口=调 AI)
├──────────────────────────────┤
│                              │
│   对话消息流 (含工具活动卡)     │  ← 唯一常驻面
│   [AI 渲染的内联卡片/页面]      │
│                              │
├──────────────────────────────┤
│ [输入区: 多行/附件/建议]        │
└──────────────────────────────┘
   ☰ 点开 → 会话抽屉 (AI 渲染或极简内置)
```

- **会话**: 左滑抽屉 (内置极简: 列表/新建/删除, ~100 行) — 或完全对话化 ("开个新会话")。
- **设置**: 不再有设置页。AI 配置/主题/认证全部通过对话完成, AI 渲染表单卡片收集输入。
- **文件/工作区**: 对话驱动。AI 用 cap.edit/cap.workspace 干活, 结果渲染成卡片; "看看项目结构"
  → AI 渲染一棵树卡片。
- **AI 渲染形态**: 仅内联卡片 (消息流内)。
- 优点: 最贴近"无应用"愿景; 代码量最小 (删比加多); 移动端天然成立; 全部精力投入对话品质。
- 缺点: 复杂产物 (长文件/大表) 挤在消息流里; 无常驻空间, 多任务弱。
- 工作量: **S** (1-2 个会话轮次; 大头是删除与对话品质)。

### 方案 B — 对话 + 画布 (Chat + Canvas, Claude Artifacts 形态)

```
┌────────┬─────────────────────┬──────────────┐
│ 会话轨  │   对话流             │  画布 Stage   │
│ (可折叠)│   消息 + 工具卡      │  [页面][文件] │
│ 32px   │   [内联卡片]         │  [表][悬浮窗] │
│        │   → "弹出到大图" ⤢   │  Tab 化/可拖拽│
├────────┴─────────────────────┴──────────────┤
│ 输入区                                       │
└─────────────────────────────────────────────┘
```

- 左 32px 图标轨 (会话/画布列表/设置→全由 AI 渲染的入口), 中对话, 右画布。
- AI 渲染的 UI 有两个去处: 小结果内联卡片, 大产物推送画布 (Tab 化, 可拖出成悬浮窗叠放)。
- 画布是**通用舞台**: 文件树、代码预览 (接 cap.edit read 行号高亮)、表格、表单、仪表盘——全是
  AI 渲染的 artifact, 壳不知道它们是什么。
- 优点: 对话为主但复杂产物有空间; 现代 AI 产品的成熟范式; 悬浮窗作为画布内形态保留; 移动端
  画布变全屏卡片栈。
- 缺点: 要建画布容器 + Tab/窗管理 (~壳里最重的部分); 有滑回"应用"惯性。
- 工作量: **M-L** (2-3 个会话轮次)。

### 方案 C — AI 桌面 (悬浮窗最大化, OS 形态)

```
┌─────────────────────────────────────────────┐
│  ┌─对话悬浮窗─┐   ┌─AI渲染: 文件树─┐          │
│  │           │   │               │  可拖拽/  │
│  └───────────┘   └───────────────┘  缩放/叠放│
│        ┌─AI渲染: 设置表单─┐                  │
│        └─────────────────┘                  │
│ [Dock: 对话 ◉ · 文件树 · 设置]               │
└─────────────────────────────────────────────┘
```

- 页面即桌面, **一切 UI 都是悬浮窗** (含对话本身), AI 通过 cap.ui.window 开/关/聚焦/布局窗口;
  Dock 显示存活窗口。
- Sky 变成 "AI 生成应用的浏览器" — 最激进地实现 capability-OS 叙事。
- 优点: 完全兑现"无应用"; 多任务最强; 与 Polaris 的窗口管理基因呼应。
- 缺点: 窗口管理器 (拖拽/缩放/z序/焦点/持久化) 工程最重; 移动端需要完全另一套 (窗口→全屏栈);
  AI 需学窗口 API, 失控时桌面混乱; 最容易过度工程。
- 工作量: **L** (3-5 个会话轮次)。

### 推荐: A 为骨架, 吸收 C 的悬浮窗作为渲染形态 (即 A+)

理由: 用户核心诉求排序 = 对话体验 > AI 实时渲染 > 悬浮窗。A 一步到位兑现前两者; 悬浮窗不需要
完整"桌面/任务栏", 只需要一个**轻量窗口管理器** (~200 行: 拖拽头/关闭/聚焦 z 序/记住位置), 作为
`cap.ui.window` 的呈现层, 让 AI 的大产物既可以内联也可以开窗。这样避开 C 的全部重工程, 又拿到
悬浮窗的体验。等画布/多任务真有需求, 再长成 B (窗口管理器是 B 的画布的前置件, 不浪费)。

## 3. 公共底座 (无论选哪个方案都要做)

### 3.1 渲染协议升级 (核心投资) — cap.ui.* 扩展

| 新增/改造 | 说明 |
|---|---|
| `cap.ui.window` | AI 开/关/聚焦悬浮窗: `{action:'open', title, width, height, x?, y?, component:{html,css,js}}` → 返回 windowId; `close/focus/move` |
| `cap.ui.component` 增强 | 挂载目标增加 `window:<id>` (渲染进指定窗) 与 `inline` (内联卡片); 生命周期回调 `onClose/onResize` 进 `__sky` |
| `__sky` 扩展 | 加 `window` (自身窗口操作), `confirm()` (危险操作确认卡), `navigate(sessionId)`, `toast()` |
| 渲染流式化 | AI 可以分块推送一个组件 (先骨架后数据) — 借用 stream.chunk 通道 |
| 组件持久化 | 窗口/卡片状态入 UI State (kv), 刷新恢复 |

**安全边界 (必须正视)**: AI 渲染的 js 现在以同源权限执行, 能读到 localStorage 里的认证 token、
能 dispatch 一切 cap。单用户自托管可接受; 若未来多用户, 需把不可信组件挪进 sandbox iframe
(空 origin + postMessage 桥)。**本周期明确声明: 同源执行, 单用户信任模型。**

### 3.2 对话体验升级 (「未来感」的本体, 比布局更重要)

- **停止生成** (AbortController 贯穿 ai.chat 流式链) + 重新生成 + 编辑重发
- 消息渲染: 流式 Markdown 增量解析、代码高亮、一键复制、代码块折叠
- 工具活动卡升级: 实时显示 AI 正在调什么 cap (icon + 参数摘要 + 耗时), 折叠策略保留
- 欢迎屏: 无会话时显示建议指令 (可点击, 点了即发送) — "无应用"的引导全靠这里
- 输入区: 多行 textarea 自适应高度、`/` 快捷指令 (可选)、Enter/Shift+Enter
- 消息分组: 长对话按轮次折叠 (Polaris 已有范式)

### 3.3 会话模型修正 (bug #1 的根治)

- `newSession()` → create + `clearChat()` + 聚焦输入框 + 顶栏同步; 流式中禁止新建
- 会话切换统一走 `loadSessionIntoChat` (从 history 渲染, 视图=存储)
- 发送前无会话 → `ensureSession` 已有, 保留
- 内置会话抽屉保留最小操作集 (新建/切换/删除/重命名), 视觉极简; 更花哨的管理界面让 AI 渲染

### 3.4 文件浏览器与旧面板处置

| 部件 | 处置 | 理由 |
|---|---|---|
| LeftPanel 文件树 | **删除** (用户已批准) | 死装饰物; 文件访问 = AI 用 cap.edit/cap.workspace + 渲染树卡片/开窗 |
| LeftPanel 能力列表 | 删除 (对话里问 "你有什么能力" → AI 渲染) | |
| LeftPanel 会话列表 | 收缩为极简抽屉 | 高频操作值得内置 |
| RightPanel (config 挂载区) | 删除 — config 回归对话 | |
| ActivityBar | 方案 A: 删除; B: 收缩为图标轨 | |
| Settings 覆盖层 (7 tab) | 拆: AI 配置/主题/认证 → 对话 + AI 渲染表单; 数据存储/关于 → AI 渲染 | "无应用"下不保留传统设置页 |
| workspace-plugin 树深度 | 提到 4-5 层 + 懒加载 (按目录取子树), 服务 AI 渲染树卡片 | cap 层扩展, 保留 |

### 3.5 cap 层拓展清单 (保留全部 31 个, 新增)

- `cap.ui.window` / `cap.ui.component` 增强 / `cap.ui.artifact` (可选, B 方案)
- `cap.ai stop` (或 stream 协议加 abort 消息)
- `cap.session` 不变 (前端语义修正即可)
- `cap.workspace`: 懒加载子树 action (`tree {path}`), 深度放宽
- 远期: `cap.search` 已并入 cap.edit; `cap.git` 按需

## 7. 脱离电脑: 三条路线

| 路线 | 形态 | 前提 | 评估 |
|---|---|---|---|
| **① PWA + 远程 Core** | 手机装 PWA, Core 跑在电脑/NAS/VPS | 同局域网或 VPN | 近期最实际。**关键坑: PWA 安装要求 secure context —— 局域网 IP + HTTP 不满足**, 三个解法: Termux localhost ✓ / Tailscale (HTTPS MagicDNS) ✓ / 自签证书 (麻烦) |
| **② Termux 本机跑 Core** (Android) | 手机自己 = 服务器 + 客户端, 真正离线脱离电脑 | Android + Termux + Node ≥22 | **sky 架构恰好为此而生**: 0 运行时 npm 依赖、node:sqlite 内置 (无原生编译)、零编译 TS 直跑。localhost 是 secure context → PWA 可装。cap.bash 在 Termux 直接可用 (AI 可操作手机文件, workspace 指向 ~/storage/shared)。iOS 无对应方案 |
| ③ nodejs-mobile 嵌 APK | 真原生 App | Capacitor 构建链 | 最重; 收益=图标/后台保活/分发。后期再议 |

### 架构现状对路线②的友好度审计

- ✅ 0 运行时依赖 (package.json dependencies 为空) — Termux 无 node-gyp 痛苦
- ✅ node:sqlite 内置 (Node ≥22.5; Termux nodejs-lts 22.x/24.x 满足)
- ✅ 零编译: tsx 直跑 TS, ARM 无障碍
- ✅ 认证已就绪 (PWA 存 token 于 localStorage; Termux 本机 localhost 可不开强制认证)
- ⚠️ **`ws` 实际是运行时依赖却在 devDependencies** — `npm install --production` 会漏装, WS 直接挂。必须挪到 dependencies (P0 级一行修)
- ⚠️ 服务器 bind 0.0.0.0: 本机用无碍, 对外暴露需开强制认证 (已有)
- ⚠️ Termux 后台限制: 需要 termux-wake-lock, 否则锁屏即断

### PWA 具体缺口 (Core 侧)

- `GET /manifest.webmanifest` + 图标 192/512 (maskable png; 可由 SVG 生成)
- service worker: 缓存 Shell HTML (单文件恰好友好), API/WS 永不缓存, 离线提示页
- standalone 显示 + theme-color + apple-touch-icon (iOS 添加主屏兼容)
