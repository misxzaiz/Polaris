# Sky 前端实施方案 v3 —「无声的界面」(Silent Interface)

> 目标：一个**没有导航、没有面板、没有设置页堆积**的单屏对话界面。
> AI 不只会回答 —— 它**实时替你调整**对话内容、工作区、界面形态。
> 交互极其舒适：响应跟手、视觉克制、绝不打扰。
>
> 关联：`cap.ai.chat`(流式工具)、`cap.form`(表单闭环)、`cap.ui.*`(契约保留)、
> WS 事件(`form`/`form-answered`/`shell.open`/`summary`)。

---

## 0. 一句话结论

**一个带 token 设置薄壳的对话流 + 一个 AI 随时可写、实时回传的"活画布"。**
用户只敲字；AI 经 `cap.*` 实时改对话内容/工作区/界面；前端被动接收事件、把"正在发生"变成舒适可见。

---

## 1. 核心交互模型（极简到只剩一条河）

```
┌────────────────────────────────────────────┐
│  [●]                    [打开时] [⚙ token]    │   ← 极简顶栏(默认隐藏, 呼出)
├────────────────────────────────────────────┤
│                                            │
│      对话流（user / AI / 实时卡片）           │
│      整个主区域，一条时间河流                │
│                                            │
├────────────────────────────────────────────┤
│  [ 输入框 ................................ ] │
└────────────────────────────────────────────┘
```

- **没有侧栏、没有会话列表、没有工作区树、没有设置页**。
  一个单页：输入 + 一条河 + 极简 3 项。
- 会话持久化交给后端 `cap.session`/`cap.history`，前端**不管理会话**。
- 工作区调整 = AI 经 `cap.workspace`/`cap.edit` 直接做，前端不做工作区 UI。

---

## 2. 技术栈

| 项 | 选型 | 理由 |
|---|---|---|
| 框架 | 原生 TS + **no framework** | 单屏、状态极小；避免框架桥接占用心智 |
| 渲染 | 原生 DOM + CSS | 无虚拟 DOM 负担；流式 chunk 直接插文本 |
| Markdown | `marked` + `DOMPurify` | 代码块/表格/内联；XSS 必须净化 |
| 样式 | 单个 CSS + CSS 变量 | `cap.ui.theme` 热更 = 改变量 |
| 构建 | Vite → `dist/` | 后端静态托管；dev 用 Vite dev 代理 |
| 依赖 | 只加 `marked` + `dompurify` | 极简 |

> 不用 React 的理由同前：AI 实时注入的是"HTML 片段 + 作用域 CSS"，原生 DOM 足够，
> 且零框架让交互延迟最小 —— 符合"极致舒适"目标。

## 3. 与后端的实时通路（WS 就好，不造协议）

后端已就绪的 WS 事件，前端**直接消费**完成"AI 实时调整"：

| 事件 | 前端响应 |
|---|---|
| `stream.chunk` | 追加当前 AI 消息文本 |
| `stream.reasoning` | 折叠的思考链（可展开） |
| `stream.tool` / `toolResult` | 工具调用指示条（"AI 正在调 cap.workspace…"） |
| `stream.end` | 收尾 |
| `form` | 渲染表单卡片（`cap.form` schema 驱动） |
| `form-answered` / `form-skipped` | 表单卡片切完成态 |
| `ui.window` | 打开/关闭浮窗（AI 渲染的悬浮内容） |
| `ui.update` | UI 状态变更 → 应用前端（样式/主题） |

**反馈回路（core）**：前端提交 → `POST /api/dispatch` → `reply` 回最近一次 → 事件回声。
用户看到"AI 在做什么"（tool/不可见）→ 结果同步落回河边。

## 4. 界面：3 个"容器" + 1 个常驻浮窗

不堆以下部件 —— 只在需要时由 AI 经 `cap.ui` 出现：

### 4.1 对话流容器（唯一主界面）
- 消息 = 块：`user` / `assistant`(含 markdown/代码/表格) / `form` / `system`(折叠)。
- **折叠的"过程"**：工具调用、思考链默认收起为一个小条（`◆ 调用了 cap.workspace`），
  点击展开 —— AI 动作"可见但不打扰"。
- 流式自动滚到底；当用户上翻时暂停跟滚（自然锚点）。

### 4.2 浮窗（`cap.ui.window`）
- 复杂 UI（表格/可视化/代码 diff）由 AI 开浮窗，可在对话流旁或全屏。
- ≤640px 自动变手机底部抽屉 —— 你之前的既定规则保留，舒适。

### 4.3 表单卡（`cap.form` schema 驱动）
- 字段 = string/number/boolean/textarea/select/secret。
- `read=none` 时只显示字段名（值不落 DOM，服务端强制）。
- 提交回执态（`form-answered` 后卡自动收起为「已完成 ✓」）。

### 4.4 极简 token 设置（唯一的"设置"）

**这是唯一在 UI 里暴露的开关**，且做成极轻：

```
┌─ (→ 点右上 ●) ─────────────┐
│  基础配置                    │
│  baseUrl      [ ________ ]  │
│  apiKey       [ •••••••• ]  │
│  model        [ gpt-4o ▼ ]  │
│  [保存]                      │
└─────────────────────────────┘
```

- 只 3 项；`apiKey` 值不落 DOM（autocomplete off / type=password）。
- 保存走 `POST /api/config` → 立即生效，无重启。
- 不用无 UI：仅此一项设，刻意忽略会话/工作区/引擎 高级配置 —— 需求明说"仅基础 token"。

## 5. 交互节奏（"舒服"的核心，不只是视觉）

| 时刻 | 行为 |
|---|---|
| 发送 | 输入框回车即发；**不打断**用户滚动 |
| AI 思考 | 只显示 `◆ 思考中` 或可折叠条，不闪不跳 |
| 工具 | 同一行的极简进度（cap 名 + 进行中…），不刷频 |
| 出错 | 底部小 toast，不弹窗；有"重试" |
| 表单 | 出现即聚焦第一个字段；回车提交；ESC 跳过 |
| 全部 | 触摸/键盘均可用；无动画开销；暗色默认+跟随系统 |

**设计摔杆**：界面上只存在"必需 + 此刻情感"的东西；压缩器收纳历史上非必需的东西——
`stream.reasoning`、tool call;、旧的表单都已折叠，不占视觉。

## 6. 目录结构（新增 `sky/web/`）

```
sky/web/
├─ index.html            — 单页壳(引入 vite 入口)
├─ vite.config.ts        — dev 代理 /api + /ws → 9825
├─ src/
│  ├─ main.ts            — 入口：认证(已验证 token) → 建 WS → 订阅 → render
│  ├─ api.ts             — 对 /api/dispatch 的薄封装
│  ├─ ws.ts              — WS 重连(指数退避) + 事件路由
│  ├─ state.ts           — 极简前端状态(消息流/表单/浮窗) — 无 React
│  ├─ render/
│  │  ├─ chat.ts         — 消息流渲染(chunk 追加)
│  │  ├─ form.ts         — 表单卡片
│  │  ├─ window.ts       — 浮窗渲染
│  │  └─ theme.ts        — 应用 cap.ui.theme token
│  └─ styles.css         — 全局 CSS 变量 + 排版
└─ dist/                 — vite build 产物(后端静态托管)
```

## 7. 验收清单

- [ ] `pnpm dev`(或 `vite`) → 单屏对话流
- [ ] 任意输入 → 流式 chunk 追加、tool call 折叠
- [ ] AI `cap.form` 拉起表单卡 → 提交 → 收起为 ✓
- [ ] AI 开浮窗 → 可拖可关、手机转抽屉
- [ ] 点右上 ⚙ → 只有 token 3 项 → 保存立即生效
- [ ] 无会话列表/无工作区树/无导航 —— 界面只有"输入 + 河 + 极简 3 项"
- [ ] 滚动舒适: 流式 跟滚、上翻暂停、无跳变
- [ ] XSS: 所有 `cap.ui`/markdown 过 DOMPurify

---

## 8. 明确不做（边界）

- ❌ 不做会话列表/管理 UI（后端 `cap.history` 已有）
- ❌ 不做工作区树/文件管理器 UI（`cap.edit`/`cap.workspace` 由 AI 直接操作，无 UI）
- ❌ 不做插件页/高级设置/主题编辑器（`cap.ui.*` 契约保留给 AI 用，不是用户界面）
- ❌ 不做 PWA/SW 首版（桌面先单页，后续可加）
- ❌ 不做"科幻化"的装饰动画 —— **领先感来自交互的舒适与克制，不是视觉炫技**

---

## 9. 建议落地顺序（phase）

- **P0（壳 + 流）**：单页 + WS 连接 + 输入 → 流式渲染 → token 设置 → markdown。
- **P1（AI 实时）**：tool call / reasoning 折叠条；`cap.form` 表单卡；浮窗渲染。
- **P2（舒适打磨）**：滚动锚点、异常重试、空状态、极简主题。
- P3（可选）：PWA、多账号记忆。

> 单页实现的话工时可控制在 ~1 天到 ~2 天（不含联调）。
