# AI 主动陪伴助手 — 架构分析与设计

> 版本：v0.1（分析阶段）
> 日期：2026-08-22
> 状态：设计稿（待验证）

---

## 1. 概念定义

**"AI 主动陪伴助手"** 是一个结合了主动性、陪伴感、学习引导和游戏化激励的 Proactive AI 系统。
它不同于纯情感陪伴（Replika）或纯工具（Claude Desktop），而是在 **Polaris 开发者工作流**中，
作为"姐姐型伙伴"主动带着用户**集成新内容、学习新技能、完成真实项目**。

---

## 2. 核心设计原则（来自调研证据）

| 原则 | 来源 | 含义 |
|------|------|------|
| **上下文感知第一** | arXiv 2502.18658, Microsoft 2025, Tavus 2025 | 主动内容必须基于用户当前项目、近期活动、提问历史，杜绝泛泛而谈 |
| **尊重用户主权** | ACM CHI 2024 "Better to Ask Than Assume" | 所有主动行为可被"推迟/拒绝/关闭"，透明可审计 |
| **低打扰、高价值** | Meurisch 2021 (cited 139), MDPI 2024 | 默认低频（1-2次/天）+ 温和呈现（卡片/侧栏），不弹窗打扰 |
| **带用户做成事** | 学习型陪伴研究 | 每一轮主动内容应有明确小目标、动手环节、产出物、进度记录 |
| **游戏化激励** | Duolingo 研究 | 进度条、连击、成就、成长感让坚持不枯燥 |
| **长期记忆** | Reddit/Character.AI 用户痛点 | 记住用户学过什么、做过什么、偏好什么 |

## 4. 与现有系统的复用关系

| 现有系统 | 复用方式 | 改造点 |
|----------|----------|--------|
| **polarisPetStore** | 成就系统、计数器、情绪状态 | 新增"学习型"成就类型（skill_learned, quest_completed），新增 companion 专属事件 |
| **voiceCompanion** | 人格模板、system prompt 注入 | 新增长文本模式（非语音）的人格模板，重写 buildCompanionSystemPrompt |
| **scheduler (Rust)** | 定时触发机制、任务持久化、协议模板 | 新增 companion 任务类型，触发时调用 LLM 生成内容 |
| **autoModeStore** | 自定义规则编辑模式 | 新增 companion 配置规则编辑 |
| **eventRouter** | 事件订阅机制 | 新增 companion 事件类型 |
| **engine-registry** | 引擎选择 | 可用于 companion 内容生成引擎 |

## 5. 分阶段路线图

### Phase 0 — 基础工具（本次实施，不集成主 UI）
构建独立的、可测试的基础模块：

1. **Companion 记忆模块** (`companionMemory.ts`)
   - 用户活动记录（sessions, edits, builds, chats）
   - 学习进度追踪
   - 交互历史持久化
   - 可独立运行（localStorage/JSONL）

2. **Companion 触发决策引擎** (`companionTrigger.ts`)
   - 定时触发策略（基于 scheduler）
   - 空闲检测触发（基于 inactivity）
   - 事件触发（build fail/success, session end, error spike）
   - 疲劳抑制（频率限制、内容多样性）
   - 可独立测试

3. **Companion 内容策划引擎** (`companionContent.ts`)
   - 上下文分析 → 生成主动内容 prompt
   - 内容类型（学习建议、项目洞察、挑战、趣味知识）
   - 内容模板系统
   - 可独立测试

4. **Companion 人格系统** (`companionPersona.ts`)
   - 人格配置（名字、性格、语气）
   - 长期记忆注入
   - 学习路径建议

5. **Companion 配置文件** (`companionConfig.ts`)
   - 全部行为可配置（频率、内容类型、人格、时间窗口）
   - 默认值（保守：1次/天，仅在工作时间）

### Phase 1 — 主 UI 集成（后续）
- 侧栏 Companion 面板
- 主动卡片渲染
- 成就系统扩展
- 设置面板

### Phase 2 — 高级功能（后续）
- 基于项目的学习路径
- 多轮对话式陪伴
- 与 voiceCompanion 联动

## 6. 技术决策

### 为什么不直接集成到主应用？
- 用户要求"先实现基础工具待验证后才能集成"
- 模块化设计：所有基础工具可独立测试
- 风险隔离：主动行为可能影响用户体验，需先验证
- 渐进式构建：先验证 Trigger/Content 引擎的正确性

### 数据持久化设计
- 使用 JSONL 文件存储（对标 dialogStorage 的 OPFS/localStorage 双轨）
- 配置用 localStorage（对标 configStore）
- 与现有 polarisPetStore 成就计数器共享数据

### 测试策略
- 单元测试：Trigger 决策逻辑、Content 模板渲染、Config 校验
- 集成测试：Memory 读写、交互流程
- 模拟测试：Mock 引擎响应，验证内容质量

## 7. 交互流程

```
[用户在 Polaris 中工作]
       │
       ▼
[Companion Trigger 引擎检测触发条件]
       │
       ├─ 定时触发（每 8 小时）
       ├─ 事件触发（build fail / session end）
       └─ 空闲触发（5 分钟无操作）
       │
       ▼
[疲劳抑制检查：频率 < 阈值？内容不重复？]
       │
       ▼
[Companion Content 引擎生成内容]
       │
       ├─ 读 Memory（用户近期活动、项目状态）
       ├─ 读 Config（用户偏好、人格设置）
       └─ 调用 LLM 生成个性化主动内容
       │
       ▼
[呈现：温和卡片在侧栏]
       │
       ├─ 用户可以：查看、忽略、推迟(1h)、永久关闭此类型
       │
       ▼
[用户与内容互动]
       │
       ├─ 点击"开始" → 进入新对话/任务
       ├─ 标记"完成" → 记录进度 + 成就检测
       └─ 忽略 → 更新 memory（下次不推类似内容）
```

## 8. 内容类型示例

| 类型 | 触发条件 | 内容示例 | 用户动作 |
|------|----------|----------|----------|
| **项目洞察** | 项目文件变更 | "我注意到你最近在改 scheduler 模块，要不要试试新的 Protocol Task 模式？" | 点击"带我看看" |
| **学习挑战** | 用户使用了某个过时 API | "你刚用的 API 在 v2 已废弃，用新 API 可以更简洁 — 想试试重写这一段吗？" | 点击"开始挑战" |
| **技能探索** | 用户从未用过某个功能 | "Polaris 有个 MCP 插件系统，你还没试过 — 要不要花 5 分钟集成一个？" | 点击"教我" |
| **成就祝贺** | 新成就解锁 | "恭喜达到 10000 行代码！今天有个新技能想学吗？" | 点击"看看" |
| **趣味知识** | 低频率 | "你知道 Rust 的 ? 运算符其实最早来自草稿还是社区提案吗？" | 无动作（纯趣味） |
| **回顾总结** | 一天结束 | "今天你改了 8 个文件，跑了 3 次构建，学了一个新 API — 不错！" | 点击"查看详情" |

## 9. 风险与缓解

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| 用户觉得打扰 | 用户体验下降 | 默认低频、渐进式呈现、一键关闭 |
| 内容质量差（泛泛而谈） | 信任下降 | 严格基于上下文，无上下文不主动 |
| 疲劳抑制失误 | 过度推送 | 多层抑制（频率、多样性、时间窗口、用户反馈） |
| 隐私顾虑 | 用户担忧 | 本地处理、不发送数据到外部、透明日志 |
| 与现有系统冲突 | 重复通知 | 复用 eventRouter 统一管理所有通知 |
