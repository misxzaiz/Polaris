实施方案

Phase 1 — 数据层：tier 字段注入

  1. 修改 Polaris-plugin/schemas/index.schema.json — plugins.items 加 tier 枚举
  2. 修改 Polaris-plugin/index.json — 18 个插件逐个加 tier 值
  3. 修改 src/plugin-system/types.ts — PolarisPluginManifest 加 tier?: 'production' | 'beta' | 'demo'
  4. 修改 src-tauri/src/models/plugin.rs — DiscoveredPluginManifest 加 tier 字段

Phase 2 — 前端渲染：PluginTab 卡片

  1. PluginCard 折叠态 + 展开态显示 tier badge（绿色/蓝色/灰色）
  2. 折叠态摘要行增加 tier 标识
  3. demo 插件默认 opacity 降低 0.6（视觉淡化）

Phase 3 — 前端渲染：MarketplacePanel 商城

  1. 商城列表按 Production → Beta → Demo 分组展示
  2. 等级过滤栏（全部 / Production / Beta / Demo）
  3. 详情面板展示 tier badge
  4. 默认隐藏 Demo 插件（需主动切换过滤才显示）

Phase 4 — 默认推断逻辑

  1. 插件 id 以 demo. 开头且未显式设 tier → 自动视为 demo
  2. 插件 id 以 polaris. 开头且未显式设 tier → 自动视为 beta
  3. 其他未设置 → 视为 beta（保守 default）
附：发现的额外问题

API 客户端三胞胎乱象：

  • polaris-api v1.1.0 — 最早版本，已重构
  • polaris-http v1.2.0 — 基于 RELAY 架构重构
  • polaris-api-client v1.0.1 — 又一个 API 客户端，功能高度重叠

这三个插件做几乎一样的事，同时出现在活动中栏和商城中，造成视觉混乱。建议择一保留（polaris-http 功能最完整），其余标记 deprecated 或从 index.json 移除。
