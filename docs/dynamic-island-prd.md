# Polaris 灵动岛（Dynamic Island）进度浮层 PRD

> 状态：待评审 ｜ 日期：2026-08-29 ｜ 配套可点击原型：`docs/dynamic-island-prototype.html`
> 关联：`docs/claude-code-task-workflow-prd.md`（TaskBoard / AgentRun / Workflow 已落地的三块 UI）

---

## 1. 问题

TaskBoard / AgentRun / Workflow 三块运行态 UI 已落地，但它们都**长在消息流里**：

1. **进度不可见**：消息往下走，进度块被顶出视口。用户滚动回看历史时，完全不知道当前跑到哪了。
   实测：一个 10 任务的 run，进度条出现后平均 2~3 条消息就被顶出屏幕。
2. **没有全局感**：并行跑 3 个 subagent + 1 个 workflow 时，状态分散在三个块里，没有一处能看「现在总共在干嘛」。
3. **定位成本高**：想看某个任务的详情，只能手动滚动寻找那个块。

## 2. 目标

- **任何时刻一眼看到当前处理进度**，不依赖滚动位置。
- **点击展开看全部运行态**（任务板 / agent 列表 / workflow 阶段），**再点定位**跳到消息流对应块。
- **空闲时零占用**——不跑任务时它不存在，不与输入区/导航件抢空间。

**非目标**：
- 不替代消息流内的 TaskBoard / AgentRun / Workflow 块（它们是历史记录，岛是运行态遥控器）。
- 不做多会话聚合（v1 只聚合当前会话的运行态）。
- 不做系统级悬浮窗（不跨应用）。

## 3. 位置与层级

```
┌─────────────────────────────────────────┐
│              ╭──────────────╮            │ ← 灵动岛（顶部居中，absolute）
│  ┌─────────────────────────────────┐    │
│  │         消息流 (Virtuoso)        │    │
│  │  [用户消息]                       │    │
│  │  [TaskBoard ▓▓▓▓░░ 3/10]        │    │
│  │  [assistant 回复...]             │    │
│  └─────────────────────────────────┘    │
│  [输入框........................] [发送] │
└─────────────────────────────────────────┘
```

- 挂载点：`EnhancedChatMessages.tsx` 的消息区容器（`flex-1 min-h-0 relative`），与
  `ChatNavigator` / `ScrollToBottomButton` 同层，`absolute top-3 left-1/2 -translate-x-1/2`。
- z-index：高于消息流，低于模态（同 ChatNavigator 现有层级）。
- 宽度：折叠态 max-w-[420px]，展开态 max-w-[560px]，均超宽截断。

## 4. 状态机

```
        ┌─────────┐  有运行态   ┌─────────┐  点击   ┌─────────┐
        │ hidden  │ ─────────→ │ compact │ ─────→ │ expanded│
        └─────────┘            └─────────┘ ←───── └─────────┘
            ↑                       ↑ 点击外部/Esc
            │                       │
            │  ┌─────────────┐      │ 全部完成
            └──│  collapsed  │←─────┘ (停留 5s 让用户确认结果)
               │ (已完成降级) │── 5s 后无交互 ──→ hidden
               └─────────────┘
```

- **hidden**：无运行态。不渲染。
- **compact**（折叠态）：有运行中活动。单行胶囊，运行中活动优先轮播。
- **expanded**（展开态）：面板，运行中卡片在上，已完成卡片折叠在底部分组。
- **collapsed**（已完成降级）：全部活动已完成时进入。岛缩为小记录条
  `✓ 完成 · 3 项 · 3m42s [展开回看]`，停留 5 秒；用户无交互则退场，
  有交互（点击展开回看）则保持 expanded 直到手动关闭。

**多窗口**：岛是 per-session 的——每个会话视图（`SessionMessagesView`）
独立挂载自己的岛，订阅各自的 session store。多窗口并行时每个格子各有岛，
互不干扰。切换会话标签时岛的状态跟随对应 session 的 store。

## 5. 折叠态设计

```
╭──────────────────────────────────────────────╮
│ ◎  任务 4/10 ▓▓▓░░░  ·  general-purpose ◐ 2m │
╰──────────────────────────────────────────────╯
```

单行，从左到右：

| 元素 | 内容 | 规则 |
|---|---|---|
| 状态点 | ◎ 呼吸动画 | 蓝=运行，绿=刚完成(2s)，红=有失败 |
| 进度段 | `任务 4/10` + 微型进度条 | 有 TaskBoard 时显示；无则显示当前活动块名 |
| 分隔 | `·` | 有多段时才显示 |
| 活动项 | 运行中 agent 的 `activeForm` / agentType | 超 24 字符截断；hover 显示全文 |
| 耗时 | `◐ 2m` | 该 run 已持续时长 |

优先级：**运行中活动优先显示**。
- 有运行中活动时，折叠态只轮播运行中的（已完成的不出现在折叠态轮播）。
- 全部已完成时，折叠态降级为 `✓ 完成 · N 项 · 时长` 小记录条（见 §4 collapsed）。
- 具体类型优先级：TaskBoard 进度 > AgentRun 状态 > Workflow phase > progressMessage 兜底。
- 多活动并存时轮播（3s 一换），hover 暂停轮播。

## 6. 展开态设计

```
╭────────────────────────────────────────────────────╮
│  当前运行                                    ─ ✕  │
│ ┌────────────────────────────────────────────┐    │
│ │ ▓ 任务板  4/10 · 1 运行 · 1 阻塞   [定位 →] │    │
│ │ ▓▓▓▓▓▓░░░░░░░░░░░░░░  40%                  │    │
│ │   ◐ 重构会话历史模块 ← #3 · 更新 12 次       │    │
│ └────────────────────────────────────────────┘    │
│ ┌────────────────────────────────────────────┐    │
│ │ ◈ agent  general-purpose  2m31s    [定位 →] │    │
│ │   14 工具 (9 完成) · 正在读取 event_parser.rs │    │
│ └────────────────────────────────────────────┘    │
│ ┌────────────────────────────────────────────┐    │
│ │ ⚙ workflow  Phase 2/3 对抗审计              │    │
│ └────────────────────────────────────────────┘    │
╰────────────────────────────────────────────────────╯
```

每类运行态一张卡（最多 3 类 + progressMessage 兜底行）：

- **卡头**：类型图标 + 类型名 + 摘要 + `[定位 →]` 按钮
- **卡体**：该类型的运行细节（任务板显示当前进行中项；agent 显示工具统计；workflow 显示 phase）
- **定位跳转**：点击后收起面板 + Virtuoso `scrollToIndex` 到对应 block 所在消息，目标块高亮 1.5s
- **排序**：运行中卡片在上（按开始时间倒序，最新在上），已完成卡片折叠到底部分组
  `▾ 已完成 (2)` 可展开回看，默认收起。避免已完成项挤占运行中项的视觉。

## 7. 数据源（全部现成，无后端改动）

| 数据 | 来源 | 说明 |
|---|---|---|
| 任务板进度 | 订阅 store `currentMessage.blocks` 中最新 `task_board` 块 | completed/inProgress/total 现成 |
| Agent 运行态 | 最新 `agent_run` 块（status=running） | toolCalls 统计现成 |
| Workflow 阶段 | 最新 workflow 工具块（status=running） | v1 显示「运行中」+ block.name |
| 兜底文案 | store `progressMessage` | progress 事件现成 |
| run 时长 | 活动块 startedAt 至今 | 前端计时 |

**实现要点**：不新建 store——用 zustand `subscribeWithSelector` 订阅 currentMessage.blocks，
派生出一个 `useRuntimeSummary()` selector hook，岛组件独立文件，挂载点一行接入。

## 8. 交互细节

- **滚动行为**：用户向上滚动时岛**保持可见**（这正是它的核心价值）；autoScroll 恢复时也不隐藏。
- **点击岛**：切换 expanded。expanded 时点击外部或 Esc 收起。
- **定位跳转**：收起面板 → 滚动到目标块 → 目标块 ring 高亮 1.5s（复用现有 scrollToMessage）。
- **完成退场**（修订）：不立即消失。全部运行态结束时进入 collapsed 态：
  显示 `✓ 完成 · N 项 · 时长` 小记录条，停留 5 秒。期间用户点击则展开回看（保持 expanded），
  无交互则平滑退场（opacity 淡出 + 高度收起）。已完成的卡片在展开态折叠在底部
  `▾ 已完成 (N)` 分组，不与运行中混排。
- **部分完成**：仍有运行中活动时，已完成的卡片自动移到底部折叠分组，折叠态只轮播运行中的。
- **失败提示**：任一 agent 失败，状态点变红，展开卡显示 error 摘要一行；失败项不折叠（置顶显示直到用户处理）。
- **流式中断**：中断时立即显示「⏹ 已中断」，1s 后收起。

## 9. 验收标准

- V1 空闲时岛不渲染，消息区无任何额外占位。
- V2 运行中，用户滚到任意位置，岛始终可见且进度数字正确。
- V3 点击展开能看到三类运行卡；点击「定位」能跳到对应块并高亮。
- V4 多活动并存时折叠态轮播，hover 暂停。
- V5 运行结束 1.5s 内退场，无残留。
- V6 岛的展开/收起不打断流式渲染（无布局抖动，absolute 定位不推挤消息）。

| I1 | 岛组件骨架 + compact 态（订阅 task_board + progressMessage） | 0.5d |
