### 关键设计

1. **状态是计算结果不是存储值**：`compute_status_from_events` 从事件日志推导 running/error（配对 start/end），与案例 3 前端算法一致
2. **排他锁不在本阶段接入 dispatch 链路**：只落仲裁命令（`session_request_start` 已 running 则拒绝），真正接进 dispatch 链路留到阶段 4
3. **事件日志与消息日志同库**（`<DataRoot>/session-v2/messages.db`），schema v2 新增 `session_events` + `session_records`
4. **seq 分配**：`next_seq` 事务内取 `MAX(seq)+1`，多进程安全
5. **CAS 乐观锁**：`session_append_message` / `session_update_metadata` 带 expected_version，版本不匹配拒绝
6. **对账命令对齐前端 `ReconcileResult`**（missing/extra/statusMismatch/serverStatus，camelCase）
