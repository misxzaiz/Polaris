# PRD：V2SessionKernel 接入与 isStreaming 消费方改造（阶段 4）

> 版本：v1.0 ｜ 状态：草案 ｜ 创建：2026-09-27

## 1. 背景与问题

### 1.1 现状

Polaris 的 AI 会话体系在前端内存态维护会话状态（`SessionStoreManager` + `persistedSeq` + `conversationIdToStoreId` + LRU），试图支撑跨设备并发实时协作。`01-根因分析.md` 已确认 6 个根因导致跨设备场景下消息丢失/中断：

| # | 根因 | 状态 |
|---|---|---|
| 1 | JSONL 并发写无锁 → 覆写吞追加（致命） | ✅ 阶段 1a 已解决（SQLite append-only） |
| 2 | conversationId 反向索引重启丢失 → 孤儿会话 | 🔄 阶段 4 解决（注册表持久化） |
| 3 | streaming 状态跨设备不可靠 → 中断/卡死 | 🔄 阶段 4 解决（后端权威） |
| 4 | LRU 驱逐 + 无条件自动创建 → 会话分裂 | 🔄 阶段 4 解决（注册表恢复） |
| 5 | persistedSeq 水位跨设备不协调 → 重复/错序 | 🔄 阶段 4 解决（后端 seq 权威） |
| 6 | resume gap 全量覆盖非原子 → 恢复期间丢事件 | 🔄 阶段 4 解决（快照合并） |

### 1.2 已完成的准备工作

- 阶段 0（`686e2db8`）：可执行状态机 + 6 能力接口，24 tests
- 案例 1~5（`a277db9c`~`9412469b`）：5 个关键假设全部验证成立
- 阶段 1a/1b（`000508f2`）：后端 SQLite MessageLog + 命令层 + V2MessageLog
- 阶段 2（`eabf3cfd`）：后端状态权威（事件日志 + 仲裁 + 对账 + Registry）15 命令
- 阶段 3（`abdfa39b`）：LegacySessionKernel 桥接，139 tests 全绿

### 1.3 问题

**前端内存态状态是跨设备不可靠的根源**（`01-根因分析.md` 根本矛盾）。阶段 4 之前的所有工作都是"影子运行"，尚未真正消除前端 isStreaming / persistedSeq / conversationIdToStoreId / LRU 自动创建这四个状态源。

## 2. 目标

### 2.1 产品目标

1. **跨设备会话状态一致**：任一设备发消息/中断，其他设备实时看到真实状态（running/idle/error），不再有"卡死在转圈"或"误中断"。
2. **重启/断线不丢会话**：页面重载、断线重连后，会话完整恢复，不分裂、不丢消息。
3. **后台静默会话正确运行**：标题生成/提示词优化/提交信息/压缩交接/调度器/派发任务，全部经统一内核管理，生命周期正确。
4. **为阶段 5（双设备并发验证矩阵）铺路**：V2 内核就绪后，阶段 5 可做端到端并发验证。

### 2.2 非目标

- 不做历史数据迁移（旧 JSONL 保留只读）
- 不引入插件宿主到生产（阶段 4 只保证能力接口可用）
- 不新增 UI 功能（本次是内核改造，UI 表现应无感知）

## 5. 需求详述

### 5.1 F1：V2SessionKernel

**能力接口**（来自 `capabilities.ts`，已稳定）：

- `MessageSendCapability`：sendMessage / continueChat / interrupt / regenerate / editAndResend
- `SessionLifecycleCapability`：createSession / deleteSession / switchSession / getActiveSessionId
- `StateQueryCapability`：getSessionState / getSessionSnapshot / getMessages / subscribe
- `EventHandlingCapability`：handleEvent
- `RecoveryCapability`：restoreFromHistory / resyncSession

**行为要求**：

1. `sendMessage` 前先 `requestStart`（后端仲裁），已 running 则拒绝并返回原因
2. `getSessionState` 从后端 `session_get_status` 计算结果，不读本地 isStreaming
3. `resyncSession` 调后端 `session_reconcile`，按 ReconcileResult 补齐 missing、不删 extra、校正状态
4. `subscribe` 复用后端事件流，状态变化（running/idle/error）触发 handler

### 5.2 F2：8 个 isStreaming 消费方

| # | 消费方 | 改造前依赖 | 改造后 |
|---|---|---|---|
| 1 | useMessageAutoScroll | `isStreaming` | `sessionState.state === 'running'` |
| 2 | useVoiceCompanion | `isStreaming` 边沿 | `onSessionStatusChange` 订阅 |
| 3 | commitMessageChat | currentMessage 跟随 | kernel 订阅 |
| 4 | titleGenerationService | isStreaming 下降沿 | running→idle 订阅 |
| 5 | promptOptimizeService | isStreaming 下降沿 | running→idle 订阅 |
| 6 | contextCompactHandoff | isStreaming 回落 | running→idle 订阅 |
| 7 | dispatchTaskService | isStreaming 检查 | 后端状态检查 |
| 8 | sessionStoreManager | streaming 转入后台 | 后端状态查询 |

**新增共享 Hook**：`useKernelSessionState(sessionId)` 返回 `{ state, isStreaming, error }`，内部 `getSessionState` + `subscribe`。

### 5.3 F4：后端事件写入

| 时机 | 事件 | 字段 |
|---|---|---|
| start 成功 | `session_start` | conversationId, deviceId, seq |
| 流式结束 | `session_end` | reason: completed/aborted/error |
| interrupt | `session_end` | reason: aborted |
| 出错 | `error` | errorMessage |

**约束**：事件写入失败仅告警，不阻断主流程（增强而非前置依赖）。

### 5.4 F6：消除前端状态源

| 状态源 | 现状 | 移除后 |
|---|---|---|
| `isStreaming` | store 字段 | 后端状态推导（消费方经 kernel 查询） |
| `persistedSeq` | 前端水位 | 后端 seq 权威 |
| `conversationIdToStoreId` | 内存 Map | 后端注册表 |
| LRU 自动创建 | 无条件创建孤儿 | 注册表恢复 + 对账 |
