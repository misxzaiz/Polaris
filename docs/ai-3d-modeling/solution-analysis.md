# 方案选型分析

> 目标：让 AI 驱动 3D 建模工具，生成可爱卡通角色（小人/小动物等），并支持动作动画。
> 约束：用户电脑配置不高（无独立 GPU），可接受安装必要软件。

---

## 1. 核心需求拆解

| 需求 | 优先级 | 说明 |
|------|--------|------|
| 可爱卡通角色建模 | P0 | 圆润 Q 版，低多边形，色彩鲜明 |
| 动作/动画 | P0 | 走路、挥手、跳跃等循环动作 |
| AI 驱动 | P0 | AI 写脚本/指令，工具执行，不是 AI 端到端生成 |
| 流畅运行 | P0 | 低配机器（CPU only）可预览，不卡顿 |
| 可导出 | P1 | 导出 glTF/FBX/STL 等格式 |
| 外观合格 | P0 | 不要求真实感，但不能粗糙，观感需达标 |
| 可多次迭代 | P1 | 用户可提出修改，AI 调整后重新生成 |

---

## 2. 候选方案全景

### 2.1 方案 A：Three.js 程序化建模

| 维度 | 评估 |
|------|------|
| **原理** | AI 生成 Three.js JS 代码，用几何体（球体/圆柱/盒子）拼装角色 |
| **安装** | 零安装，浏览器/WebView 直接运行 |
| **建模能力** | ⭐⭐⭐ 可拼装 Q 版角色，但复杂造型（毛发、不规则）难做 |
| **动画能力** | ⭐ **致命短板** — 无骨骼系统，拼装体无法做自然动作 |
| **流畅度** | ⭐⭐⭐⭐⭐ 即时渲染 |
| **AI 友好度** | ⭐⭐⭐⭐⭐ Three.js 文档丰富，AI 生成成功率高 |
| **导出** | 可导出 glTF 但动画骨架缺失 |

**结论：❌ 动画能力不足，不适合需要角色动作的场景。**

### 2.2 方案 B：Blender bpy 脚本（推荐）

| 维度 | 评估 |
|------|------|
| **原理** | AI 生成 Python bpy 脚本，Blender headless 执行建模 + 绑定 + 动画 |
| **安装** | 需安装 Blender（~500MB），CPU 即可，无需 GPU |
| **建模能力** | ⭐⭐⭐⭐⭐ 完整建模能力，可做任何造型 |
| **动画能力** | ⭐⭐⭐⭐⭐ 完整骨骼/蒙皮/动画系统，配合预设动作库 |
| **流畅度** | ⭐⭐⭐ 后台生成，前端 Three.js 预览不卡 |
| **AI 友好度** | ⭐⭐⭐⭐ bpy API 规则性强，AI 写几何体拼装脚本很可靠 |
| **导出** | 全格式（glTF/FBX/OBJ/STL/VRM） |

**结论：✅ 建模 + 动画全覆盖，唯一免费全能方案。**

### 2.3 方案 C：Manifold 几何内核

| 维度 | 评估 |
|------|------|
| **原理** | JS/WASM 底层几何内核，布尔运算/倒角/拉伸等 |
| **安装** | 零安装，npm 包 ~3MB |
| **建模能力** | ⭐⭐⭐⭐ 几何操作能力强，但不擅长不规则造型 |
| **动画能力** | ⭐ **无动画系统** — 纯几何体，无骨骼/蒙皮 |
| **流畅度** | ⭐⭐⭐⭐⭐ WebAssembly 性能极好 |
| **AI 友好度** | ⭐⭐⭐⭐ JS API，AI 好写 |
| **导出** | 可导出 glTF/STL/OBJ |

**结论：❌ 无动画能力，可作 Blender 的补充（前端预览/快速原型），不能独立使用。**

### 2.4 方案 D：Trimesh (Python)

| 维度 | 评估 |
|------|------|
| **原理** | Python 纯库，`pip install trimesh`，参数化建模 + 布尔运算 |
| **安装** | 需装 Python 包（~20MB），无独立软件 |
| **建模能力** | ⭐⭐⭐⭐ 适合几何体组合，不擅长有机造型 |
| **动画能力** | ⭐ **无动画系统** |
| **流畅度** | ⭐⭐⭐⭐ 纯 CPU 跑 |
| **AI 友好度** | ⭐⭐⭐⭐⭐ Python 语法，AI 最擅长 |
| **导出** | STL/OBJ/glTF/PLY |

**结论：❌ 无动画，建模偏硬表面，不适合卡通角色。**

### 2.5 方案 E：Blender + Mixamo 管线

| 维度 | 评估 |
|------|------|
| **原理** | Blender 建模 → 导出 FBX → Adobe Mixamo 自动绑定+动作 → 回导 |
| **安装** | Blender + 网页访问 Mixamo |
| **建模能力** | ⭐⭐⭐⭐⭐ |
| **动画能力** | ⭐⭐⭐⭐⭐+ Mixamo 有数百个专业动作 |
| **流畅度** | ⭐⭐⭐ 需网络上传/下载 Mixamo |
| **AI 友好度** | ⭐⭐⭐ Half 自动化（需要手动上传 Mixamo 或脚本自动化） |
| **导出** | 全格式 |

**结论：✅ 可作为 Phase 2 的动画增强，不作为主方案。**

## 4. 选型决策：Blender 为主，三段式协作

### 4.1 架构设计

```
用户输入（文字描述角色+动作需求）
    │
    ▼
┌──────────────────────────────────┐
│      AI 层（大模型）              │
│  1. 解析用户需求                  │
│  2. 选择骨架模板（小人/四足/宠物）  │
│  3. 生成 bpy 建模脚本             │
│  4. 选择/参数化预设动作             │
└──────────┬───────────────────────┘
           │ bpy 脚本
           ▼
┌──────────────────────────────────┐
│      ⚙️ 建模执行层（Blender）      │
│  1. headless 模式执行脚本          │
│  2. 几何体拼装 → 细分圆滑 → 材质    │
│  3. 自动绑定骨架模板               │
│  4. 套用预设动作                   │
│  5. 导出 glTF/FBX                 │
└──────────┬───────────────────────┘
           │ glTF 模型文件
           ▼
┌──────────────────────────────────┐
│      🎨 渲染层（Three.js）         │
│  1. 加载 glTF 模型                 │
│  2. 实时预览（旋转/缩放/播放动画）   │
│  3. 用户反馈 → 再次迭代             │
│  4. 导出下载                       │
└──────────────────────────────────┘
```

### 4.2 为什么 Blender 是最优解

1. **建模能力覆盖所有需求**：几何体拼装、细分曲面、圆滑、倒角、材质——Q 版角色所有需求都能满足
2. **动画系统完整**：Armature（骨骼）+ Weight Paint（蒙皮）+ Action（动画）——这是其他方案做不到的
3. **bpy 脚本 AI 好写**：几何体操作规则性强，是 AI 代码生成最擅长的领域
4. **headless 模式**：不需要打开 Blender 窗口，后台运行，结果导出后前端预览
5. **免费**：无授权费用，无使用限制
6. **导出格式最全**：glTF（Web 直接加载）、FBX（游戏引擎）、VRM（二次元角色标准）

### 4.3 动画策略（关键）

AI 不直接调动画帧，改用**模板骨架 + 预设动作库**：

- **骨架模板**：预置 3 套基础骨架（Q 版小人、四足动物、Q 版宠物）
- **预设动作库**：每套骨架配 6-8 个循环动作（待机/idle、走路、挥手、跳跃、摇头、打招呼、跑步、跳舞）
- **AI 的工作**：选骨架 + 选动作 + 调参数（幅度、速度、循环次数）

这样建模质量稳定，动画不会失调，AI 不需要掌握复杂的骨骼动画技巧。

## 5. 风险与缓解

| 风险 | 等级 | 缓解措施 |
|------|------|----------|
| bpy 脚本出错（API 版本不兼容） | 中 | 锁定 Blender 版本（4.2 LTS），脚本模板化，AI 在模板上修改 |
| 自动绑定骨架不符合 Q 版比例 | 中 | 骨架模板手动调好，AI 只调整位置/缩放，不改变拓扑结构 |
| 预设动作不够丰富 | 低 | 起始 6-8 个动作足够，后续可扩展（Mixamo 导入） |
| Blender 安装用户不熟悉 | 低 | 安装指引 + 一键检测脚本（检测是否已安装 + 版本号） |
| headless 渲染结果与预览不一致 | 低 | 统一材质库（所有角色使用同一套 Toon 材质），前后端一致 |
| 生成速度慢 | 中 | 复杂模型可加进度反馈，第一版限制多边形数量（~5000 面以内） |

| 组件 | 选型 | 版本 | 备注 |
|------|------|------|------|

## 7. 不选择其他方案的原因

- **Three.js 程序化**：无骨骼动画，无法做角色动作
- **Manifold**：无骨骼动画，适合硬表面建模
- **Trimesh**：无骨骼动画，偏硬表面
- **Cinema 4D / Maya**：付费软件，没必要
- **VRoid (VRM 编辑器)**：只能做人类角色，不支持小动物，且不是脚本化操作
- **AI 端到端生成（Meshy/Tripo）**：依赖云端 GPU，结果不可控，无法做动画，无法迭代修调
