Learning · 01

Multica 是什么？

一个让人类和 AI Agent 像同一支团队协作的开源项目 — 本质是「项目管理的界面 + 你电脑上的 AI 编码工具」的组合。

开源 可自托管 20+ AI 工具 人类 + Agent 混编

一句话理解

把 Claude Code / Codex 等 AI 编程工具，当成可以分配任务、认领任务、汇报进度的团队成员。 你在看板上建 Issue → 分配给某个 Agent → 它在你自己的电脑上执行 → 结果回写到 Issue。
核心心法：Multica 只负责「记录 + 协调」，真正干活（改代码、跑命令）发生在连接到你账号的某台电脑上。

类似

GitHub Issues / Jira / 飞书项目 的项目管理界面
＋
按「团队成员」方式驱动本地 AI 编程 CLI

不像

不是又一个 ChatGPT 聊天框
不是云端帮你写代码的 IDE
不是模型路由/推理网关
Learning · 02

核心对象（5 个）

理解这 5 个词，Multica 的交互就全通了。

对象作用类比
Workspace一个协作空间，隔离项目/团队Jira 项目 / 飞书群
Issue一条要完成的工作，含描述 + 讨论 + 负责人GitHub Issue / 工单
Agent一个 AI 成员配置：用什么工具、什么模型、什么指令团队里的一个成员
RunAgent 认领 Issue 后的一次执行（排队 → 执行 → 回写）一次构建 / 一次任务执行
Runtime连接到你电脑的执行端（daemon + 本地 AI 工具）CI 的 runner
关系链：Workspace 里有多个 Issue；Issue 分配给 Agent；Agent 触发一次 Run；Run 由某台电脑的 Runtime 认领执行。
Learning · 03

一次 Run 的完整路径

Multica 官方文档的「How a run works」交互化演示。

1
Issue 提供上下文

Issue 里装着工作描述、讨论、负责人。分配给 Agent 时，系统读取该 Agent 的指令、模型、技能、runtime 配置。

2
Multica 创建 Run

Run 进入队列。如果没有 runtime 在线，就等待在那里。

3
Runtime 认领 Run

一台在线电脑的 runtime 认领 Run，调用该 Agent 配置的 AI 编码工具（如 Claude Code）。

4
AI 工具在本地执行

工具读取工作目录、跑命令、产出结果 — 全都在你自己电脑上。

5
结果回写 Issue

进度、评论、结果出现在 Issue 的时间线和执行日志里。

Interactive · 06

4 种触发 Agent 的方式

Agent 永远不会自己开始干活 — 每一次 Run 都由显式动作触发。

📋
分配 Issue

最常用的方式。把 Issue 指派给 Agent，Multica 自动创建 Run。

💬
@提及

在评论里 @claude，像 @同事 一样让其参与讨论或干活。

🗨️
直接聊天

打开与某个 Agent 的会话，直接发消息（单轮或多轮追问）。

🤖
Autopilot

预定义规则自动触发（如 Issue 状态变化时自动派 QA 复验）。

Architecture · 07

数据边界：记录 vs 执行

Multica 官方安全模型的核心 — 也是它和 Polaris 结合最自然的地方。

📍 Multica（服务器 / 云端）

  • 📄Workspaces / Issues / 评论 / 状态
  • ⚙️Agent 配置与 Skills
  • 📊Run 状态、记录、结果

💻 连接的电脑

  • 🔑AI 工具及其凭证
  • 📁代码目录与本地文件
  • ⚡实际文件修改与命令执行
云版和自托管边界相同。唯一例外：写入 Agent 的 custom_env 会存到 Multica 服务器，执行时再下发 — 所以密钥类内容不要放 custom_env。
Integration · 08

与 Polaris 的结合点

Polaris 已经是「多引擎本地执行环境」，Multica 是「团队协作协调层」— 两者天然咬合。

Multica — 记录 / 协调

📋Issue / Run 队列 — 团队协作前端
🧠Agent 配置 — 谁、用什么工具、什么模型
🔔触发 — 分配 / @提及 / 聊天 / Autopilot

Polaris — 执行（Runtime 角色）

⚙️多引擎 — Claude Code / Codex / 插件引擎
🧩富工具 — 浏览器 / MCP / 插件
📱移动端 — 随时监控 Agent 进度

4 种结合路径（按投入排序）

方向做法投入收益
1. 理念借鉴把 Issue 持久化 + 全局看板搬进 Polaris 现有 dispatch 体系低内部多智能体协作体验对齐
2. MCP 集成Polaris 会话通过 MCP 操作 Multica 的 workspace/issue/run中Agent 能读 Multica 上下文并回写
3. 当 RuntimePolaris 桌面端作为 Multica 的执行端，认领 Run 用本地引擎干中高双向增益：Multica 获得富执行，Polaris 获得团队前端
4. 合并移植把 Multica 模型整体并入 Polaris高⚠️ 与已有 dispatch/roster 重叠，不推荐
当前会话改造（session-v2）顺带同向：Polaris 正在把「状态权威」从前端内存搬到后端数据库 — 这恰好把地基打成了「将来当 Multica Runtime」的样子，但两者目前是独立的两条线。
