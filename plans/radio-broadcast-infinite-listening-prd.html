无限畅听电台

定位：想到什么听什么，永远有下一集 —— 交互式 PRD 原型 · 左侧为需求文档，右侧可点击操作（点话题开台 → 字幕自动跟读 → 插话/换台/定时 → 内容库续播）

1定位与北极星

一句话：一个由 AI 无限生成的个人电台——用户用一句话开台，AI 连续创作并朗读，随时换台、插话、囤积、回听。不是「语音播报工具」，而是「听的内容本身」。

对标差异：番茄畅听/懒人听书 = 有版权内容库的「畅听」；NotebookLM = 围绕你上传文档的播客（有门槛）；Spotify AI DJ = 歌单主持。Polaris = 零内容门槛的即时无限电台 + 背后是真引擎可插话（录音式产品做不到）。

🎯 北极星：人均单次收听时长7 日回访开台率插话使用率

2用户与场景

  • 睡前：「讲个明朝那些事，无限续」→ 定时 30 分钟 + 播完本段停 + 淡出。
  • 通勤：新闻早报连播 + 实时字幕（地铁嘈杂）+ 锁屏控制。
  • 学习陪伴：经济学基础连播 + 插话提问「刚才那个机会成本再讲讲」。
  • 家务摸鱼：后台连播 + 双主播闲聊感（P3）。

3核心体验闭环

开台（一句话/点话题，3 秒出声）→ 畅听（无限连播·字幕跟读）→ 随意（上滑换台·插话·定时）→ 沉淀（好听进内容库·喜欢音色进音色库）→ 回来（续播·订阅更新）

4功能地图（原型已标注对应屏）

P0 快赢纯前端为主，数据已在

  • 实时字幕跟读（屏 B 主视觉）——数据源已有 nowPlayingText
  • 倍速 / 睡眠定时（含「播完本段」+ 淡出，屏 B 控制条）
  • 锁屏 MediaSession 控制
  • 合成缓存 + 音频落 data root + GC（cap.voice 前置债）

P1 资产层cap.voice + 两库

  • cap.voice 能力（synthesize / voices / library / jobs）
  • 内容库：历史单集·续播·收藏·下载（屏 C）
  • 音色库：预置 + 设计 + 克隆持久化（屏 D）
  • 引擎解绑（mimo-tts 插件 ≠ 唯一，edge-tts 兜底）

P2 无限体验质变点

  • 上滑换台：直播中岔到新话题不断音频感（屏 B 顶部）
  • 插话互动：随时提问，AI 回答后继续播（屏 B 弹层）
  • 预生成囤积：睡前一键囤 N 集离线听（屏 C 绿色任务卡）
  • 节目/单集模型 + AI 管家工具（AI 整理/删除/合集）

P3 生态

  • 双主播对话（NotebookLM 式）· 订阅式更新 · 车机蓝牙深适配 · 多端同步

用户渴望来自哪里我们的落点
实时字幕（嘈杂环境/无障碍/记好句）Apple Podcasts 官方转文字、讯飞有声逐字高亮屏 B 字幕跟读，P0
断点续播/回放所有播客 App 标配屏 C 续播卡，P1（依赖库）
倍速+跳静音+睡眠定时播客/听书 App 标配，差评高频词屏 B 控制条，P0

无限刷的随机感抖音式无限下滑心智迁移到「听」上滑换台，P2
囤积离线听番茄畅听下载、播客自动下载预生成 job，P2

6技术依赖与风险（如实）

  • cap.voice：MiMo design/clone 为无状态 API（每次重传描述/样本），音色库本质 = 持久化参数并命名。
  • 插件 stdio 单实例串行合成是预生成吞吐瓶颈；base64 每句 ~200KB。
  • 9861 端口硬编码 → 收敛到核心侧托管（P1 一并解）。
  • MiMo 免费额度未知 → 缓存（hash(text+voice+style)）是成本护城河。

7非目标（本期不做）

  • 不做版权内容库、不做社交/评论、不做主播形象虚拟人、不做 UGC 分享社区。
