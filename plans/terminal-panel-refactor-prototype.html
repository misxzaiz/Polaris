渲染后端对比 DOM renderer vs WebGL renderer
现状 · DOM renderer scrollback 10000
每行 = 1 个 DOM 节点 · 大输出/快滚时重排成本高
scrollback: 10000 满载时视口外仍有数千节点参与重排
目标 · WebGL renderer GPU 合成
整片 <canvas> 纹理 · 字形批量绘制
引入 @xterm/addon-webgl · DOM renderer 作 fallback（WebGL 不可用降级）
已识别痛点 来自 TerminalPanel.tsx 实读
无 WebGL 渲染
TerminalPanel.tsx:8-11
仅 FitAddon + WebLinksAddon，默认 DOM renderer。大输出/快速滚动场景渲染开销高于 WebGL/Canvas。
resize 高频抖动
TerminalPanel.tsx:176-186
ResizeObserver 高频回调，每次 resize 触发 fit + IPC 两次同步调用。已用 rAF + setTimeout(100) 双层 debounce 缓解，本质仍贵。
输出逐字节解码
TerminalPanel.tsx:147-150
atob 后 for 循环逐字节写 Uint8Array，高频大块输出（cat 大文件）下有 CPU 成本，无批量写入。
初始化竞态
TerminalPanel.tsx:84-88
容器零尺寸时 xterm RenderService 初始化竞态，已 guard 但首次挂载可能延迟一帧。
优化方案 · 三步走 按确定性×收益÷成本排序
1
引入 @xterm/addon-webgl
终端初始化时挂载 WebGLAddon，xterm.loadAddon(new WebGLAddon())。WebGL context 不可用时 catch 降级回 DOM renderer。几行代码，官方支持。
收益 高
成本 低
2
输出解码批量写入
TerminalPanel.tsx:147-150 逐字节 for 循环改为 Uint8Array.from(binary, c => c.charCodeAt(0)) 一次性构造，或直接 xterm.write(binary)（xterm 支持字符串入参）。大块输出 CPU 成本骤降。
收益 中
成本 低
3
resize debounce 收紧 + IPC 合并
现状 100ms debounce 偏松（拖拽尾迹明显）。改为 60ms + 拖拽中只 fit 不 resize（拖拽结束才发 IPC），减少同步 IPC 次数。保留 rAF 合帧。
收益 中
成本 低
