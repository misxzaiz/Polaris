拆分方案 · 三步走 克制拆分 · 不做无收益大重构
1
React.memo 包裹 + props 引用审计
L155 裸 export function 改 memo(ChatInput)。审计 30 个 store hook 与 props 流,确保引用稳定,否则 memo 形同虚设。需 React DevTools Profiler 实测确认。
收益 高
成本 中
2
拆优化浮层为独立组件 PromptOptimizeOverlay
L544–714 浮层逻辑 + L1846–2039 共 ~365 行 JSX 抽出,独立 memo,仅优化模式开启时渲染。主组件 JSX 减 ~190 行。4 个 OPTIMIZE_* 配置数组(L95–122)外移到 input/constants.ts。
收益 高
成本 中
3
两处大 switch 暂不拆
handleInputChange(L741–1067 触发符路由)与 selectSuggestion(L1107–1285 类型分发)逻辑耦合深,拆出需重构数据流,收益不如前两步直接。留作后续,标记为已知技术债。
收益 低
成本 高
落地约束（AGENTS.md §三 / §七）
• ChatInput 经 Chat barrel 静态 import 进首屏(App.tsx:11)——memo 不影响首屏体积,只降运行时重渲染
• 改动前先读 src/components/Chat/input/ChatInput.tsx 与对应测试(§二.1)
• 改后跑 pnpm exec tsc --noEmit + pnpm lint + pnpm test:run(§七)
• memo 有效性需 Profiler 实测——若 store hook 返回值引用不稳,memo 失效;失败时回退到 step 2 先行
• 不动协议/状态模型(§二.4 spec 要求),纯组件内部重构,无需补 plan
