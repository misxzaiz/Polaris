# S3 — 跨端投影订阅：快照 + 增量帧 + gap repair（spec）

> 状态：提案 · 归属：前端（src/renderer）+ 传输层 · 依赖：S1、S2

---

## 1. 目标

让前端 **实时持有后端权威投影**（会话列表 + 每会话运行态），实现：另一端新建/删除/状态变化在本端自动可见；断线重连增量补齐、不丢不重；彻底移除 `V2SessionKernel.subscribe` 的 **1s setInterval 轮询**兜底。

对齐 ZCode：`subscribeSessionsIndexV4` / `onDynamicSessionsIndexFrame`（首拉快照 + 增量帧 + gap repair + 乐观合并）。

## 2. 现状（已核实）

- `src/session-v2/kernel/v2-kernel.ts`（518 行）：`V2SessionKernel.subscribe` 用 1s 轮询比对快照，无推送。
- `src/services/eventRouter.ts`（228 行）：单例路由，事件按 `_routeSessionId` 分发；无 topic 维度。
- `src/session-v2/core/v2-session-event-log.ts`：已有事件日志 + 快照合并基础。
- `src/services/dialogStorage/service.ts`：JSONL 只落消息。

## 3. 目标架构

### 3.1 订阅协议（依赖 S1 命令）

```text
首拉：  session_list_workspace(workspaceKey)        → snapshot + lastSeq
订阅：  session_subscribe(workspaceKey, afterSeq)   → 增量帧流
补齐：  session_subscribe_resync(workspaceKey, lastSeq) → delta | 全量
```

帧（复用 chat-event 通道，`topic` 前缀）：

```ts
type SubscribeFrame =
  | { topic: 'sessions-index/<wsKey>'; kind: 'upsert' | 'delete' | 'snapshot'; ... }
  | { topic: 'conversation/<sessionId>'; ... }   // 已有对话帧，新增 topic 分流
```

### 3.2 前端订阅管理器（新增 `subscribeWorkspaceSessions`）

```ts
class WorkspaceSessionsSubscription {
  wsKey: string
  lastSeq: number
  buffer: SessionProjectionDelta[]       // 应用前暂存，避免 UI 抖动
  connected: boolean

  async start(): void
    // 1) session_list_workspace → snapshot 写入桶
    // 2) session_subscribe(afterSeq) → 增量帧应用
  async resync(): void
    // gap 超阈值 → 全量；否则 delta 补齐
  onFrame(frame): void
    // 按 topic 分流到桶/会话 store（对齐 ZCode onDynamicSessionsIndexFrame）
  optimistic(event): void
    // 本端发起的命令先乐观应用，帧到达后替换（对齐 ZCode 乐观合并）
}
```

### 3.3 连接管理（对齐 ZCode connectionManager）

- 订阅生命周期跟 **workspace 桶激活**：桶激活 → 订阅；桶失活 → 退订（断开会话数可追踪）。
- 断线检测：transport `disconnect` 事件 → 置 `connected=false`；重连成功 → `resync()`。
- **移除** `V2SessionKernel.subscribe` 的轮询（S3 收尾项）；保留内核快照合并能力作为 resync 的本地投影层。

### 3.4 话题路由（改造 eventRouter）

- 事件路由维度：`topic`（sessions-index / conversation）→ workspaceKey → sessionId。
- 兜底：找不到桶不再丢弃（依赖 S2 懒加载），先挂起帧，桶就绪后重放（对齐 ZCode 订阅重放语义）。

## 4. 状态机（订阅生命周期）

```text
IDLE → CONNECTING → ACTIVE ⇄ SUSPENDED(断线) → ACTIVE(resync 后)
ACTIVE 内: 每帧校验 seq，seq 跳跃 → resync；seq 重复 → 丢弃
```

## 5. 验收

| # | 场景 | 验收 |
|---|---|---|
| 1 | 桌面新建会话 A | web 列表 <2s 出现 A，无需刷新 |
| 2 | 桌面删除 A | web 列表自动移除 |
| 3 | 桌面发送消息 | web 实时收到流式块（无轮询） |
| 4 | 断线 30s 重连 | 增量补齐；事件不重复不丢失 |
| 5 | 事件 seq 跳跃 | 触发 resync，最终一致 |
| 6 | 桶失活 | 订阅退订，无泄漏 |

## 6. 风险

- **时序**：首拉快照与增量帧之间可能有竞态 → 订阅命令必须保证「afterSeq 快照 + 帧」原子语义（S1 约定）。
- **乐观合并**：本端命令的乐观状态与后端帧冲突时，以帧为准（ZCode 同规则）。
- **改造面**：eventRouter 增加 topic 分流，会影响既有事件分发路径 → 先加路由维度、不改既有 handler 签名。
