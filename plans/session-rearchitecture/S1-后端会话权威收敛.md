# S1 — 后端会话权威收敛：sessions-index + 订阅命令（spec）

> 状态：提案 · 归属：后端（src-tauri）· 依赖：无 · 为 S2/S3 提供底座

---

## 1. 目标

把后端从「事件日志 + Registry 半成品」补齐为 **workspace 级会话权威投影**，并提供**跨端订阅命令**，使任何端都能：拉取某 workspace 的完整会话列表（快照）、订阅增量（帧流）、断线补齐（gap repair）。

对齐 ZCode：`tasksDatabase` / `taskIndexRepo`（sessions-index 投影 + workspaceKey 分桶）。

## 2. 现状（已核实）

- `services/session_state.rs`（1209 行）：`session_events` + `session_records` 表、`compute_status`、`request_start/interrupt`、`reconcile` —— **已有**。
- `commands/session_state_commands.rs`（495 行）：`session_*` 命令 —— **已有**。
- `services/session_db.rs`（626 行）：SQLite 打开/迁移。
- **缺口**：无 `sessions-index` 表（workspace 级会话列表投影）；无订阅命令；事件 `seq` 全局递增但无 workspace 维度。

## 3. 目标接口

### 3.1 数据表（新增）

```sql
-- workspace 级会话投影（权威列表；增量帧由此产生）
CREATE TABLE IF NOT EXISTS sessions_index (
  workspace_key   TEXT NOT NULL,          -- identity ?? path
  session_id      TEXT NOT NULL,          -- 前端 sessionId
  conversation_id TEXT,
  title           TEXT NOT NULL DEFAULT '',
  status          TEXT NOT NULL DEFAULT 'idle',  -- idle|running|error
  seq             INTEGER NOT NULL,       -- 该 workspace 内会话变更序号（跨端因果序）
  updated_at      INTEGER NOT NULL,
  engine_id       TEXT NOT NULL DEFAULT '',
  workspace_id    TEXT,
  last_error      TEXT,
  started_by_device TEXT,
  PRIMARY KEY (workspace_key, session_id)
);
CREATE INDEX IF NOT EXISTS idx_sessions_index_ws_seq
  ON sessions_index(workspace_key, seq);
```

`session_events.seq` 保持全局递增（已有）；`sessions_index.seq` 是投影层的 workspace 内序号（可复用全局 seq 的某个字段，不额外自增——**每写一行投影即记录最新 seq**）。

### 3.2 RouterBus 命令（`cap.ai.chat` 或新增 `cap.session`）

```ts
// 快照 + 订阅起点
session_list_workspace({ workspaceKey, workspacePath, workspaceIdentity })
  → { sessions: SessionProjection[], lastSeq: number }

// 增量帧（chat-event 通道, topic 前缀 "sessions-index/<workspaceKey>"）
session_subscribe({ workspaceKey, afterSeq })
  → 首帧 snapshot + 后续增量帧

// 断线补齐（gap repair）
session_subscribe_resync({ workspaceKey, lastSeq })
  → { frames: SessionProjectionDelta[] }  // gap 过大时回退全量快照
```

帧协议（对齐 ZCode `sessionsIndexTopicWireCandidate`）：

```ts
type SessionsIndexFrame =
  | { kind: 'upsert'; session: SessionProjection }
  | { kind: 'delete'; sessionId: string }
  | { kind: 'snapshot'; sessions: SessionProjection[]; lastSeq: number }
```

### 3.3 写入路径（单一）

所有会话生命周期写入统一在 `session_state.rs` 内部维护 `sessions_index` 投影（同一事务）：

- `create_record` → 投影 upsert（seq 递增）
- `update_record_metadata` / `append_message_id` → 投影 upsert
- 运行态变化（`session_start` / `session_end` / `error` 事件）→ compute_status 后投影 upsert
- `delete_record` → 投影 delete（seq 递增）

禁止其他模块绕过 `session_state` 直写投影表。

## 4. 事件流

```text
发送消息 → cap.ai.chat start → session_events append(seq=N)
        → compute_status → sessions_index upsert(seq=N) → 广播聊天帧
订阅端   → session_subscribe(afterSeq) → 收到增量帧 (seq>afterSeq)
```

- 桌面 continuous：实时帧直达。
- 移动 replayable：快照 + gap repair。
- 断线重连：`session_subscribe_resync(lastSeq)` 补齐；gap 超阈值回退全量。

## 5. 验收

| # | 场景 | 验收 |
|---|---|---|
| 1 | 桌面新建会话 | `sessions_index` 出现该会话，seq 递增 |
| 2 | 会话运行态变化 | 投影 status 更新，seq 递增 |
| 3 | 删除会话 | 投影删除，seq 递增 |
| 4 | 订阅 afterSeq | 只收到 seq>afterSeq 的增量，无重复 |
| 5 | gap repair | lastSeq 之后补齐，不丢不重 |
| 6 | workspace 隔离 | 不同 workspaceKey 互不可见 |

## 6. 风险

- **seq 语义**：投影用 workspace 内 seq，避免跨 workspace 号乱。与全局 `session_events.seq` 的映射需在后端单测固定。
- **事务一致性**：投影表与事件表必须同一事务写（`BEGIN IMMEDIATE`），失败回滚。
- **性能**：订阅端数少（≤ 几端），无需 fan-out 优化；若未来扩大再抽象订阅管理器。
